# Завершение приложенного списка ревью · 17.10.2026

Исходная версия: `635ebf54d51f1ec76eed25f10c0347e1331de8ca`. Этот выпуск закрывает подтверждённые остатки из повторной сверки: полную страницу счёта, вкладки бухгалтера, неограниченную выдачу счетов, клиентские агрегаты, денежные адаптеры, внедрение лимитера и штатное восстановление через отдельную БД.

## Реализация

| Остаток | Что изменено |
|---|---|
| InvoicePage | Общий hook и Zod DTO с диалогом; реальные поля комиссии/расходов/плательщика; ролевое отсутствие суммы не превращается в ноль. |
| Бухгалтерия | Устранён двойной `/api`, страницы и поиск документов, ошибки и повтор загрузки документов/журнала. Такой же URL исправлен у 2 графиков. |
| Полные списки | `/api/invoices` всегда возвращает страницу, 100 по умолчанию, максимум 200. Глубина OFFSET ограничена 10000 совпадениями; интерфейс предлагает уточнить фильтр. |
| Итоги и детализация | SQL-агрегаты для балансов, годовых итогов и статусов документов; страницы групп и ленивые страницы вложенных счетов; выбор счёта для оплаты/переноса с поиском. |
| Экспорт | Оба XLSX-пути используют streaming writer, keyset-порции и commit строк; полный экспорт не ограничен страницей интерфейса. |
| Деньги | Decimal до строки хранения, единый диапазон numeric(15,2), half-up, откат переполнения с 400. Объектные FinancialInputs вместо 8 позиционных аргументов. |
| Контракты и DI | Общие DTO выводятся из схем, критические identity/invoicing-ответы проверяются реестром API; лимитер передаётся через composition root. |
| Восстановление | Пустая shadow DB, сверка 22 таблиц/точных сумм/документов, защитная копия текущей БД, атомарное переключение имён, health, обратное переключение при сбое. Прежняя БД сохраняется. |
| Мобильный интерфейс | Минимальная ширина основного flex-контейнера исправлена: таблица прокручивается внутри карточки, вкладки остаются в пределах экрана. |

## Архив большого объёма

Локальный PostgreSQL 16.13 (x86_64 под эмуляцией), macOS/Apple M2, Node 25.4; V8 heap ограничен 256 MiB. Синтетические 100000 счетов, 300000 расходов и 10 документов по 1 MiB. Архив 34891202 байта; создание 9.711 s, восстановление 68.484 s, дополнительная сверка всех таблиц 84.907 s. Пиковые RSS 385 MiB и heap 86 MiB; ограничение V8 heap не является ограничением RSS. Все отпечатки таблиц совпали; 10 документов восстановлены в пустую папку с совпадающими SHA-256.

## HTTP-нагрузка окончательного варианта

100000 счетов / 300000 расходов, 200 клиентов, 20 партнёров, 10 соединений; смесь 10 маршрутов в равных долях, включая запрос без page, поиск, SQL-итоги и статусы документов. Каждый уровень — минимум 100 запросов и 10 секунд. На HTTP-фазе нет загруженных актов; архивная фаза отдельно проверяет документы. Перед этим замером отключён тестовый UI-сервер; локальные тесты уже завершены. Полные результаты: [JSON измерений](2026-10-17-review-load.json).

## Границы утверждений

Нагрузочный результат относится к изолированному локальному стенду и указанной смеси запросов. Это не измеренная production capacity. Длительный soak и полный набор EXPLAIN-планов production не проводились. При больших глубинах интерфейс намеренно ограничивает OFFSET; полный экспорт использует keyset. Схемы runtime обязательны для затронутых финансовых и identity-путей; распространение схем на каждый исторический вспомогательный endpoint не заявляется. Перенос каталогов в новые бизнес-модули не требуется для подтверждённых исправлений поведения.

Ручные периоды и сохранённый исторический счётчик из предыдущего выпуска сохранены. Этот выпуск не меняет бизнес-правило использования услуг.
