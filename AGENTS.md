# Правила для агентов в FinanceDuck

## GitHub - источник истины

Основная ветка на GitHub совпадает с кодом на проде. Работа, которой нет на GitHub, не считается сделанной.

- Перед работой забрать свежую основную ветку: `git pull`.
- Каждую законченную правку закоммитить и отправить на GitHub в том же сеансе: `git push`. В конце работы не должно оставаться незакоммиченных или неотправленных изменений.
- На прод выкладывать только коммит, который уже влит в основную ветку на GitHub. `deploy/deploy.sh` проверяет это сам и останавливает выкладку.
- Срочную правку тоже сначала отправить на GitHub и влить в основную ветку, потом выкладывать.
- Настройки сервера (nginx, systemd, скрипты) хранить в `deploy/`. Если что-то изменили прямо на сервере, в тот же день перенести изменение в репозиторий.

## Зависимости

- По понедельникам Dependabot открывает PR с обновлениями: минорные версии группами, мажорные по одной. PR вливать, когда проверки зеленые. Мажорную версию сначала прочитать по описанию изменений и проверить экраны, которых она касается.
- По понедельникам CI запускается по расписанию, поэтому новые уязвимости видно заранее, а не в день выкладки.
- Намеренно не обновлены, Dependabot их пропускает:
  - TypeScript 7: typescript-eslint пока поддерживает TypeScript только до 6.0.
  - `@types/node` выше 22: типы следуют за версией Node на сервере. Обновлять вместе с Node на сервере.
- `overrides` в `package.json` закрывают уязвимости в чужих зависимостях: minimatch 11 для typescript-eslint, esbuild 0.28 для старого загрузчика drizzle-kit. При обновлении typescript-eslint и drizzle-kit проверить `npm ls minimatch esbuild`: если пакеты сами требуют исправленные версии, переопределение убрать.
