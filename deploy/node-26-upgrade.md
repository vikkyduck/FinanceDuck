# Переход сервера на Node 26

Сервер работает на Node 22, его поддержка заканчивается 30 апреля 2027. Код проверен на Node 26 LTS (26.13.1) в PR #4 от 15.11.2026: проверка типов, линтер, сборка и 306 тестов проходят, собранный сервер отвечает на вход, список счетов, PDF и Excel отчеты. Переход занимает около 20 минут. Кабинет недоступен во время двух выкладок (шаги 1 и 5, пока скрипт делает резервную копию базы и переключает релиз) и несколько секунд при перезапуске на шаге 3.

Выполняет человек или агент на Маке с SSH-доступом к серверу, тем же, что использует `deploy/deploy.sh`. Агент показывает каждую команду для сервера и выполняет ее только после подтверждения.

## Перед началом

- На Маке в папке проекта: `git pull`, рабочая копия чистая.
- Адрес сервера задается так же, как для выкладки. Все команды ниже используют переменную `S`:

```bash
export SERVER_HOST=<алиас или адрес сервера>
S="${SERVER_USER:-root}@$SERVER_HOST"
```

- Выбрать время, когда в кабинете никого нет.

## Шаг 1. Выложить обновленный код на Node 22

На проде сейчас код до обновления зависимостей, на Node 26 его не проверяли. Поэтому сначала обычная выкладка проверенного кода на старой версии Node:

```bash
./deploy/deploy.sh
```

Скрипт сам делает резервную копию базы перед переключением (`/var/finance-duck/releases/<релиз>/before-switch.dump`), проверяет здоровье сервера и фонового обработчика и при сбое возвращает предыдущий релиз.

Проверить руками: кабинет открывается, вход работает, список счетов на месте, отчет клиента в PDF скачивается. Если что-то не так, остановиться и разобраться до смены Node.

## Шаг 2. Записать исходное состояние

```bash
ssh "$S" 'node -v; npm -v; apt-cache policy nodejs | head -3'
```

Сохранить вывод: он понадобится для отката.

## Шаг 3. Установить Node 26

Установка идет из того же источника NodeSource, что и в `deploy/install.sh`. Работающие процессы продолжают использовать старую версию, пока их не перезапустить.

```bash
ssh "$S" 'curl -fsSL https://deb.nodesource.com/setup_26.x -o /root/nodesource_setup_26.sh && bash /root/nodesource_setup_26.sh'
```

```bash
ssh "$S" 'apt-get install -y nodejs && node -v'
```

`node -v` должен показать v26. После этого перезапуск, кабинет недоступен несколько секунд:

```bash
ssh "$S" 'systemctl restart finance-duck finance-duck-worker'
```

## Шаг 4. Проверить

```bash
ssh "$S" 'node -v; systemctl is-active finance-duck finance-duck-worker; curl -fsS http://127.0.0.1:5000/api/health'
```

Ожидается: v26, два раза `active`, ответ со `"status":"ok"`.

Фоновый обработчик отмечается в базе каждые 30 секунд. Время последней отметки должно быть не старше минуты:

```bash
ssh "$S" "sudo -u postgres psql -At -d finance_duck -c \"SELECT last_finished_at FROM scheduled_jobs WHERE key = 'worker-heartbeat'\""
```

Последние ошибки приложения и фонового обработчика:

```bash
ssh "$S" 'tail -n 30 /var/log/finance-duck/error.log /var/log/finance-duck/worker-error.log'
```

В браузере повторить проверку шага 1: вход, счета, PDF и Excel отчет клиента.

## Шаг 5. Повторить выкладку под Node 26

Нативных модулей в проекте нет, поэтому зависимости, поставленные под Node 22, работают и под Node 26. Повторная выкладка того же коммита поставит их заново уже новой версией npm и прогонит встроенные проверки скрипта. Лучше сделать это сейчас, а не во время срочной правки:

```bash
./deploy/deploy.sh
```

## Если что-то пошло не так: откат на Node 22

Эти команды стандартные для apt, но на этом сервере не проверялись. Перед запуском агент показывает их человеку.

```bash
ssh "$S" 'curl -fsSL https://deb.nodesource.com/setup_22.x -o /root/nodesource_setup_22.sh && bash /root/nodesource_setup_22.sh && apt-cache policy nodejs'
```

В выводе найти доступную версию 22 (вида `22.23.5-1nodesource1`) и поставить ее:

```bash
ssh "$S" 'apt-get install -y --allow-downgrades nodejs=<версия из вывода> && node -v && systemctl restart finance-duck finance-duck-worker'
```

После отката повторить проверки шага 4.

## После перехода: правки репозитория

Одним PR, после того как шаги 4 и 5 прошли:

1. `.github/workflows/check.yml`: `node-version: '22'` заменить на `'26'`.
2. `package.json`: в `engines` указать `"node": ">=26"`, в скрипте `build:server` заменить `--target=node22` на `--target=node26`, `@types/node` обновить до `^26`.
3. `deploy/deploy.sh`: в проверке версии на сервере заменить `<22` на `<26`.
4. `deploy/install.sh`: `setup_22.x` заменить на `setup_26.x`, проверку `-lt 22` на `-lt 26`, в сообщениях "Node.js 22" на "Node.js 26".
5. `deploy/README.md`: "Node.js 22.12+" заменить на "Node.js 26".
6. `.github/dependabot.yml`: убрать исключение для `@types/node`. В `AGENTS.md` убрать строку про `@types/node`.

Затем проверки (`npm run check`), PR, слияние и обычная выкладка.

## Пока есть доступ к серверу: две системные проверки

1. Настройки nginx на сервере расходятся с `deploy/nginx.conf`: заголовки безопасности в ответах прода не совпадают с файлом. Забрать реальный файл, сравнить с шаблоном и перенести отличия в `deploy/nginx.conf` отдельным PR. Шаблон остается шаблоном: домены заменить обратно на `DOMAIN_PLACEHOLDER`, строки с пометкой `# managed by Certbot` не переносить, их добавляет certbot при выпуске сертификата.

```bash
ssh "$S" 'cat /etc/nginx/sites-available/finance-duck' > /tmp/finance-duck.nginx.conf
diff deploy/nginx.conf /tmp/finance-duck.nginx.conf
```

2. Посмотреть ожидающие обновления Ubuntu и включены ли автоматические обновления безопасности. Ставить обновления системы - отдельное решение владельца:

```bash
ssh "$S" 'apt-get update -qq && apt list --upgradable 2>/dev/null | head -30; systemctl is-enabled unattended-upgrades'
```
